# VratiMe — сохранность данных при нескольких способах входа

Этот документ задаёт правило для будущего включения Google OAuth. Его цель — чтобы пользователь не терял профиль, объявления, сделки, отзывы, экобаллы и контакты при смене способа входа.

## Что уже защищает данные

В VratiMe профиль хранится в `public.profiles`, а все пользовательские данные ссылаются на один UUID из `auth.users.id`:

- объявления — `listings.user_id`;
- контакты — `profile_contacts.user_id`;
- сделки — `transactions.giver_id` и `transactions.taker_id`;
- отзывы — `reviews.from_user_id` и `reviews.to_user_id`.

Поэтому способ входа не является владельцем данных. Владельцем является один Supabase-пользователь (UUID).

## Обычный и безопасный сценарий

1. Пользователь уже вошёл по Magic Link на `name@example.com` и создал профиль.
2. Позже он выбирает Google с тем же **подтверждённым** адресом `name@example.com`.
3. Supabase автоматически связывает Google-identity с существующим пользователем.
4. UUID остаётся тем же; все существующие данные остаются на месте.

Это штатное automatic identity linking Supabase. После настройки его проверяем на тестовом пользователе: Magic Link → профиль и объявление → Google с тем же email → проверка того же UUID, профиля и объявления.

## Другой Google email

Если Google возвращает другой адрес, автоматического объединения быть не должно: одинаковое имя или номер телефона не являются безопасным доказательством владельца.

После включения OAuth добавляется экран «Способы входа» в профиль:

1. пользователь уже авторизован в прежней учётной записи;
2. нажимает «Подключить Google»;
3. завершает Google OAuth;
4. Supabase вручную связывает новую identity с текущим UUID через `supabase.auth.linkIdentity({ provider: 'google' })`;
5. интерфейс показывает, что Google подключён.

Для этого в настройках Supabase включается **Allow manual linking**. Кнопка подключения доступна только внутри авторизованного профиля; никаких объединений по номеру телефона, имени или совпадению текста контакта не делать.

## Сессия в приложении

Supabase JS по умолчанию хранит сессию на устройстве и обновляет токен. Приложение не очищает эту сессию при перезагрузке: выход выполняется только явной кнопкой «Выйти». После развёртывания проверяем отдельно Chrome, Safari/iOS и установленную PWA.

## Приёмка перед включением Google

1. Войти по Magic Link, создать профиль, объявление и бронь.
2. Перезагрузить страницу и закрыть/открыть браузер — сессия и профиль на месте.
3. Войти Google с тем же email — UUID и данные те же.
4. Войти Google с другим email — новый профиль создаётся отдельно, ничего не переносится автоматически.
5. Войти в старую учётную запись и вручную подключить Google с другим email — UUID не меняется, данные на месте.
6. Убедиться, что чужие контакты, сделки и объявления по-прежнему закрыты RLS.

Источник поведения automatic и manual linking: [Supabase Identity Linking](https://supabase.com/docs/guides/auth/auth-identity-linking).
