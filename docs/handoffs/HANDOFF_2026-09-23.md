## Что осталось для выпуска

1. Собрать `dist` из текущего коммита и создать tar-архив с содержимым `dist` в корне.
2. Передать архив и `scripts/server/vratime-deploy-static-v1.sh` на Hetzner.
3. На сервере выполнить скрипт с новым release ID. Он сам сохраняет предыдущий `current` и откатывает симлинк, если HTTP/asset/release-проверка не проходит.
4. Локально выполнить `npm run test:production`; ожидается совпадение public JS/CSS, service worker и `RELEASE.txt`.
5. В браузере проверить два аккаунта на desktop и ширине 390 px: сохранённый поиск/дайджест, избранное, точка сбора, частичный резерв, встреча/неявка, временная передача и возврат.
6. Обновить `docs/CURRENT_STATE.md` и `docs/operations/RELEASE_REPORT_2026-09-23.md` фактическим release ID только после зелёной проверки домена.

## Безопасность и границы

- Не раскрывать `.env`, API keys, service role, OAuth/Tribute secrets, SSH keys, server password или резервные копии.
- Не менять пользовательскую папку `deliverables/`; новый итоговый архив добавлять отдельным именем.
- Изменять только запрошенный функционал и сопутствующие тесты/документацию.
