## 7. Решения, которые уже приняты и не должны пересматриваться без причины

1. Запрос не скрывает объявление с карты. Объявление скрывается только после принятия владельцем.
2. Контакты не открываются до принятия запроса.
3. После принятия действует 48-часовая бронь.
4. Передача завершается только после подтверждения обеими сторонами.
5. При отмене/истечении срока объявление возвращается на карту.
6. Экобаллы начисляются только после двойного подтверждения: 50 дарителю и 25 получателю.
7. Подозрительность не означает автоматическую блокировку. Система только ставит внутренние флаги для ручной проверки.
8. Общий рейтинг добровольный. Пользователь может отключить видимость, не теряя баллы.
9. Уровней должно быть больше четырёх-пяти; утверждена текущая система из 10 уровней и нелинейных порогов.
10. Адрес объявления не обязан совпадать с текущей геолокацией пользователя. Должны сохраняться поиск адреса, клик и ручное перетаскивание маркера.
11. Все пользовательские тексты должны поддерживать RU, ME и EN.
12. Интерфейс обязательно проверяется скриншотами на телефоне и компьютере перед публикацией.
13. База Supabase и старые пользователи должны сохраняться; смена домена приложения не должна создавать новую базу.
14. Публиковать новый фронтенд до успешного применения миграции нельзя.

## 9. Оставшиеся ошибки, проблемы и риски

1. `npm run db:check` завершился ошибкой `Missing SUPABASE_DB_HOST`.
   В `.env` есть только имена:
   - `VITE_SUPABASE_URL`
   - `VITE_GOOGLE_AUTH_ENABLED`
   - `VITE_SUPABASE_ANON_KEY`
   - `SUPABASE_SECRET_KEY`

   Значений `SUPABASE_DB_HOST`, `SUPABASE_DB_USER`, `SUPABASE_DB_PASSWORD` нет. Не просить и не публиковать секреты без необходимости; текущий путь — SQL Editor Supabase.

2. Локальные коммиты `2c4f42b..9671a7a` и эта актуализация HANDOFF ещё не отправлены на GitHub.

3. Фронтенд ещё не опубликован на рабочем сайте.

4. Нужен реальный E2E двумя разными пользователями:
   - пользователь A создаёт объявление;
   - пользователь B отправляет запрос;
   - объявление остаётся на карте;
   - A принимает запрос;
   - объявление исчезает с карты;
   - контакты становятся видны обеим сторонам;
   - один подтверждает передачу — сделка ещё не завершена;
   - второй подтверждает — сделка завершается, баллы начисляются;
   - отдельно проверить отмену и истечение 48 часов.

5. Поиск адреса использует публичный Nominatim. Нужно проверить запрос в живом браузере; при росте трафика потребуется собственный/платный геокодер или прокси с соблюдением политики сервиса.

6. Автоматического фонового cron для истечения броней нет. Просроченные сделки очищаются RPC `refresh_expired_deals` при загрузке карты/сделок. Для раннего этапа это принято, но в будущем лучше добавить серверный cron.

7. `supabase/APPLY_ALL_IN_SQL_EDITOR.sql` пока не дополнен новой миграцией. Основной источник истины — отдельный файл миграции. Если проект продолжает распространять one-shot bundle, его нужно обновить отдельным механическим шагом.
